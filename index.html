SmartCita — Sistema de agendamiento y control clínico

2026

Gestión de citas médicas e historiales clínicos para un consultorio veterinario.

ASP.NET Core · C# · EF Core · MediatR · FluentValidation · SQL Server · Angular

Problema

El consultorio coordinaba citas e historiales en hojas de cálculo que se desincronizaban entre recepción y los doctores. No había una fuente única de verdad ni forma de auditar cambios. La operación crecía y el error humano empezaba a costar dinero en citas duplicadas.

Decisiones clave
  • Monolito modular con Vertical Slice en lugar de capas horizontales: el dominio era pequeño y los repositorios genéricos añadían ceremonia sin beneficio.
  • MediatR para aislar casos de uso, dejando que FluentValidation interceptara en un pipeline sin mezclarse con la persistencia.
  • EF Core con transacciones explícitas en SQL Server para el flujo de agendamiento, donde una cita doble era inaceptable.
  • Corté una caché distribuida: el volumen no la justificaba y añadía una dependencia operativa que un equipo unipersonal no podía sostener.

Resultado

El endpoint de disponibilidad bajó de ~800 ms a ~200 ms tras añadir un índice compuesto en SQL Server. El flujo crítico de agendamiento quedó cubierto con pruebas de integración.

Sistema de Inventario Híbrido — Desktop + Edge Serverless

2026

Cliente de escritorio en Java sincronizado con una API en el edge de Cloudflare.

Java (Desktop) · Cloudflare Workers · Cloudflare D1 (SQLite) · REST

Problema

El inventario se manejaba en una app de escritorio Java que no sincronizaba entre sucursales. Montar un servidor tradicional implicaba costos fijos altos para una operación intermitente, y la latencia desde provincia era un problema real.

Decisiones clave
  • API en Cloudflare Workers en lugar de un VPS: cero infraestructura dedicada, despliegue en el edge y facturación por uso.
  • Cloudflare D1 (SQLite en el edge) para mantener el modelo relacional sin pagar un motor administrado que no se iba a aprovechar.
  • Modelo de datos compatible con SQL para poder migrar a Postgres o SQL Server si la operación lo exigía, sin reescribir el dominio.

→
HTTPS · REST
→
Cloudflare Workers
→
Cloudflare D1

Sincronización sin servidor dedicado: la lógica vive en el edge y el dato cerca del usuario.

Resultado

Latencia de consulta notablemente reducida frente a un servidor centralizado y costo de infraestructura fijo eliminado. La operación queda cubierta sin servidor que administrar.

CalculoEstribos — Automatización de metrados de acero

2026

Aplicación web que reemplaza el cálculo manual de estribos de construcción.

ASP.NET Core MVC · C# · Razor · Bootstrap

Problema

Los metrados de estribos se calculaban a mano en obra, propensos a error en longitudes de corte y con desperdicio de material difícil de estimar. Un error de cálculo en una varilla significa dinero perdido y, a veces, retrabajo.

Decisiones clave
  • Lógica de dominio separada de la vista: las reglas de corte, desperdicio y geometría viven en el dominio, no en el controlador ni en Razor.
  • Validación de parámetros geométricos en el dominio, con mensajes que explican el error al usuario en lugar de solo rechazarlo.
  • UI deliberadamente simple en Razor + Bootstrap: el valor está en el cálculo, no en la presentación.

Reemplazó el cálculo manual eliminando errores de longitud y haciendo visible el desperdicio de material antes de comprar la varilla.
